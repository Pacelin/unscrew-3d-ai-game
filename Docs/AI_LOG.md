# Журнал работы с ИИ

Хронология: что делал человек, что агенты, как проверялось. Отсюда собирается раздел README «Процесс работы с ИИ».

## Инструменты

- **Claude Code (Opus 5.5)** — оркестратор: план, контракты, ревью, мерж.
- **Саб-агенты Claude Code** (`.claude/agents`) — параллельная разработка модулей.
- **UnityMCP** (CoplayDev/unity-mcp) — управление редактором: сцены, префабы, консоль, тесты, скриншоты.
- **dotnet test** — прогон Core-тестов вне Unity за секунды, параллельно по модулям.

**Человек:** создал Unity-проект, поставил URP, импортировал ассеты, подключил UnityMCP, сделал `git init` и `.gitignore`.

**Промпт:**

**Агент:** прочитал ТЗ (docx через python/zipfile), README ассетов, проанализировал `Level_XX.json`. Выяснил: id подряд, болтов кратно 3, `sourceLayer` везде 0 — блокировки придётся вычислять самим. Предложил архитектуру «чистое ядро + view» и набор скиллов и агентов.

**Промпт:**

**Решения агента:**
- Контракты (`Scripts/Core/Contracts`) написаны и заморожены **до** запуска параллельных агентов: это единственная точка связи модулей.

## 2026-10-29 — Этап 4.5: правила корректности уровней и правило поражения

**Промпт (человек, гейм-дизайн):**
> Вводим правила для проверки корректности уровней:
> 1. Шляпки болтов не находятся внутри меша, к которому он прикручен.
> 2. При выкручивании болт не задевает соседние меши (вместо raycast используем SphereCast с радиусом болта, на дистанцию, на которую болт выезжает при выкручивании (длина болта + отступ)).
> Выполни этот прогон на всех уровнях. Поражение при out of space работает некорректно. Поражение должно происходить только в случае, когда не осталось ходов (out of moves)…

**Агенты (параллельно):** core-dev (правило поражения, worktree `core/out-of-moves`, ~9 мин) + level-designer (валидатор и перебейк, Unity, ~14 мин).

**Результаты:**
- Правило 2: граф блокировок строится только по `SphereCastAll` (радиус = радиус шляпки, дистанция = длина × 1.15, старт — над опорной плоскостью шляпки). Геометрию болта агент измерил по мешу `Screw004`. Набор блокеров изменился у 467 из 1611 болтов.
- Правило 1: **161 нарушение** (52 шляпки утоплены целиком: L05 — 25, L18 — 15). Подтверждено скриншотами (`bake2_rule1_*.png`). Сам тест чётности лучей агент проверил на контрольных точках: середина стержня внутри владельца у 258 из 264 болтов, точка далеко снаружи — 0.
- Правило поражения: `Lost` = нет доступного болта, который можно положить в коробку или буфер. Изменения в контракте (доки), `GameSession`, `PuzzleSim`/`GreedyPolicy` и Magnet. Агент нашёл неочевидное следствие: магнит при полном буфере мог «съесть» единственный ход посреди серии → порядок снятия изменён, добавлен тест.
- Агент заметил, что после смены правила даже целенаправленно плохая игра выигрывает L12–13 → отдельная задача на перенастройку сложности.

**Решение оркестратора по правилу 1:** поле `BoltDefinition.headLift` — запечённый сдвиг болта наружу вдоль оси на глубину погружения. Применяется в бейке до свипа и во view при спавне, поэтому граф совпадает с тем, что видит игрок.

**Следующий шаг (параллельно):** level-designer запекает `headLift`; core-dev перенастраивает `DifficultyCurve` по метрике «win rate казуального игрока» (Monte-Carlo на `PuzzleSim`).

**Проверка:** после слияния `test.sh All` 288/288 на перебейканных данных.

## 2026-11-02 — Фикс тапа по болтам: только шляпка, без клика сквозь меши

**Промпт (человек):**
> Есть 2 бага: 1. Болты можно выкручивать за резьбу (клик должен проходить только по шляпке). 2. Болты можно выкручивать кликая на них сквозь другой меш (клик должен проходить только прямо по болту (шляпке), то есть кликать сквозь другие меши нельзя, нужно поправить Raycast).

**Агент (unity-integrator, main-дерево, ~15 мин):**
- Измерил меши болтов через редактор (профиль max-радиуса по высоте): все 12 префабов — одна геометрия; шляпка = верхние ~40% высоты меша, её радиус = extents.x/z.
- `BoltView.Init`: tap-коллайдер — BoxCollider, подогнанный под шляпку (центр на 0.2×высоты ниже верха меша, размер 1.15× от измеренной шляпки), вместо сферы по центру всего болта с радиусом 1.7×радиуса шляпки — она накрывала резьбу и пустоту вокруг болта.
- `BoardInput.Tap`: единый `Physics.Raycast` по всем слоям (был — только слой Bolt), тап засчитывается, только если ближайший хит — болт; в режиме дрели дополнительно `IsBoltVisible` (поведение коммита 111f175 сохранено). Закрыта вторая половина QA #6 — тап сквозь модель в обычном режиме.

**Решения:** сфера не подходит — шляпка плоский диск (высота 0.02 vs радиус 0.0335), любая сфера, накрывающая кромку, проваливается ниже шляпки на резьбу. Box в меш-локальных координатах на том же GameObject, где была сфера (пульс/детач не тронуты). Запас 15% — осознанная «прощщающесть» тапа, как было задумано изначально.

**Проблемы проверки:** первый Play Mode-прогон гнал проверки по старому уровню — `GameFlow.StartLevel` асинхронный (Loading → Tick строит view), ушёл в ложные «баги»; после ожидания `FlowState.Playing` цифры сошлись. ## 2026-11-03/04 — Бейк 6: посадка болтов, runtime-тапаемость, мгновенный ввод

**Промпт (человек, дословно):**
> 1. На втором уровне обнаружено, что болты в воздухе. Нужно проверить метод запекания, шляпка болта должна находится на поверхности меша, к которому болт прикручен, а резьба должна быть внутри меша… За основу нужно брать значения позиций с изначального конфига в UnscrewFirst20/Data, и смещаем болт по направлению резьбы в сторону "выкручивания" или "закручивания", в зависимости от изначального положения болта.
> 2. Нужно убрать задержку ввода во время анимаций, пусть болты откручиваются и улетают сразу после нажатия. Если для болта нет места - болт улетает в очередь, а если во время анимации полета появилось место в слотах для болтов - сначала доигрывается анимация появления слота и анимация полета в очередь, а после болт улетает в нужный слот. Если слот для болта нужного цвета есть сразу - болт сразу улетает на нужное место.

**Посадка (T1):** `LevelValidator.ComputeSeat` — от исходной позиции: утопленная шляпка выкручивается наружу (как раньше), висящий болт **закручивается внутрь** (отрицательный `headLift`) до касания поверхности, резьба остаётся во владельце. `headLift` стал знаковым (view/бейк/валидатор). Проверка по требованию — скилл `bolt-seat` + меню Unscrew → Check Bolt Seating (`CheckSeating`: шляпка/резьба/потенциал закручивания отдельно). L2: было 8 парящих лифтов 0.7–3.6 → стали 39 закрученных внутрь и 3 мелких наружу.

**Тапаемость — смена парадигмы.** Аналитический зонд правила 3 (бейк 5) не совпал с реальным гейтом ввода: валидатор бейка пропускал болты, которые input-кампания находила запечатанными (гроц-лучи у посаженных шляпок + модель камеры).
